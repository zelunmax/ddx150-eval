Version 2.0Closeness 1–5 per candidate; follow-up “reasonable for this HPI?” when closeness is 1–3.
每個候選診斷評接近度 1–5；給 1–3 分時追問「對 HPI 合理？」 Version 3.0Closeness 1–5 per candidate; appropriateness 1–5 per group (AMIE-style).
每個候選診斷評接近度 1–5；每組整體評適當性 1–5。 Version 4.0Two steps per case: (1) name-only closeness 1–5, duplicates merged; (2) read the case, then HPI-support 1–5 for the same list + the GT itself.
每例兩步：先只比對名稱評接近度 1–5（重複合併）；再展開病例，對同一份清單評 HPI 支持度 1–5，含 GT 本身。 Version 6.0Same three steps as V5, step-dependent layout: step 1 shows only the ground truth on the left (case hidden); step 2 shows the case, ground truth hidden; step 3 keeps the case and rates the ground truth on the right.
與 V5 相同的三步，但版面隨步驟切換：第一步左側只顯示 ground truth；第二步顯示病例、隱藏 GT；第三步保留病例，右側評 GT。 Version 6.1.2 — case selection (PI only)Free navigation + ✓/✗ per case with optional reason. Run 1 = best 100 of the 150 (989 chapter quotas, ~8:2 disease:symptom, unique GT). "Start next run" refills rejected slots from the 50 leftover cases, then from the audited pool outside the 150, until 100 are accepted. Export the final list as JSON + CSV.
病例篩選：每例 ✓／✗（可選原因）。第一輪為 150 例中最佳的 100 例；「開始下一輪」從 50 例備用、再從 150 例以外的審核池補位，直到收滿 100 例。 Version 6.1 — free navigation (PI review)Same as V6.0 but steps 2 and 3 can be opened at any time without finishing step 1, for case selection and review. Not for formal rating (separate pack id).
與 V6.0 相同，但第二、三步可隨時直接切換、不需先完成第一步，供計畫主持人瀏覽與挑選病例。不用於正式評分。 Version 5.0Three steps per case: (1) name-only closeness 1–5; (2) read the case, HPI-support 1–5 for the same list; (3) given the HPI, how fitting is the ground truth 1–5.
每例三步：先只比對名稱評接近度 1–5；再展開病例評 HPI 支持度 1–5；最後根據 HPI 評 ground truth 適合度 1–5。
